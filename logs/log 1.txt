Collector design decision
Transactions are the primary historical data source because they represent actual sales and have a very short visible history window.

Recommended service polling
- Fetch transaction pages 1-10 every 5 seconds.
- This uses about 120 requests/minute.
- Fetch 8 listing pages per 5-second cycle as a rolling listing sweep.
- This uses about 96 requests/minute.
- Total planned load is about 216 requests/minute, leaving reserve under the documented 250 requests/minute limit.

Collector features implemented
- SQLite storage.
- Reads DONUT_API_KEY from the environment.
- Stores raw JSON alongside normalized columns.
- Stores auction_sales.
- Stores auction_listing_snapshots.
- Stores market_stats.
- Stores collector_state.
- Stores item_candles_1m for OHLC/median/VWAP chart preaggregates.
- Tracks base_item_key separately from variant item_key.
- Adds transaction observation metadata:
  - collected_first_at
  - collected_last_at
  - observation_count

Item identity
- base_item_key is the plain Minecraft item id, such as minecraft:diamond_pickaxe.
- item_key is a variant identity based on item id, display name, lore, enchants, and contents.
- This allows commodity-level analytics and separate analytics for enchanted/custom variants.
